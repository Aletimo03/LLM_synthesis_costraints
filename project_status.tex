\section*{Research Objective}
The core question is:
\begin{quote}
Can an LLM generate synthesis constraints that are correct enough to support ASIC-style synthesis and timing analysis --- and, when the tools reject or under-cover them, can it repair its own output?
\end{quote}

The framework currently studies this question through four linked goals:
\begin{enumerate}[leftmargin=*,nosep]
    \item generate SDC constraints from RTL plus a target clock period,
    \item validate the constraints through a real synthesis and STA flow,
    \item classify the resulting behavior into meaningful failure or success labels,
    \item compare LLM-generated runs against trusted reference constraints,
    \item feed the tools' own diagnostics back to the model and measure whether it repairs, stalls, or regresses.
\end{enumerate}

\section*{Current Architecture}
The repository is now organized around a dedicated Python package, \texttt{pipeline/}, which implements the full experiment loop:

\begin{enumerate}[leftmargin=*,nosep]
    \item \textbf{LLM generation} via \texttt{pipeline/llm.py}. A versioned prompt template (\texttt{v1\_base} or \texttt{v2\_base}, selected at runtime) is filled with Verilog source and target period, then sent to a local Ollama model.
    \item \textbf{Output cleaning} removes reasoning tags, code fences, and non-SDC text, keeping only recognized constraint commands.
    \item \textbf{Synthesis} via \texttt{pipeline/synthesis.py}. Yosys reads the RTL, runs standard optimization and mapping passes, and invokes ABC with a liberty-based timing target.
    \item \textbf{Static Timing Analysis} via \texttt{pipeline/sta.py}. OpenSTA reads the synthesized netlist and the generated SDC, then reports WNS, TNS, minimum slack, and path-level timing behavior. The STA stage issues \emph{independent per-path-group queries} (input$\to$register, register$\to$output, register$\to$register) using \texttt{-from}/\texttt{-to} filters, so a constrained path can no longer be masked by a competing critical path at the same endpoint. This makes coverage detection reliable.
    \item \textbf{Classification} via \texttt{pipeline/classifier.py}. Each run is labeled using both tool logs and the content of the generated SDC.
    \item \textbf{Dataset logging} via \texttt{pipeline/dataset.py}. Each experiment appends one row to \texttt{results/dataset.csv}.
\end{enumerate}

A \textbf{correction ladder} runs after classification and fires on any \texttt{final\_status} $\neq$ \texttt{ok}, escalating through up to two levels that re-feed the latest SDC and its error with cumulatively stronger help. Level~1 gives the tool's own error together with the model's previous SDC (the tool's complaints where a tool objected; a precise derived statement --- which ports went untimed, which path group violates --- where the tools stay silent). Level~2 adds an object dictionary: the design's real port and net names, \texttt{[all\_registers]}, and the fact that RTL-level pin names do not survive synthesis. The level at which a run is repaired is itself the diagnosis --- a repair at level~1 was a robustness slip, at level~2 a namespace limitation, and a run that is never repaired points to a deeper gap. Because the dictionary is drawn from the design's own Verilog, which the model already sees, \textbf{nothing derived from the reference SDC ever reaches the model}: the ladder measures self-repair rather than hint-following. The retry budget is spent only on \texttt{v2\_base} failures, since \texttt{v1\_base} failures mostly re-measure the missing \texttt{-name}/\texttt{-clock} scaffold that \texttt{v2\_base} already fixes. The correction prompt enforces minimal edits (keep working lines identical, add nothing unless required), a rule motivated by a first symptom-only sweep in which repairs were overwhelmingly small edits while failed corrections expanded the SDC and broke previously working syntax. Each level is evaluated in its own \texttt{correction\_<n>/} directory, and the columns \texttt{initial\_status}, \texttt{correction\_path}, \texttt{corrected}, \texttt{best\_status} and \texttt{final\_status} make the full trajectory measurable.

Its placement matters. An earlier version of this loop was triggered by a \emph{synthesis} failure and sat between the synthesis call and the STA stage; it never fired once, because the SDC is not an input to Yosys (a bad constraint therefore cannot break synthesis, and \texttt{synth\_failed} is $0$ across every run recorded here) and because none of the verdicts that do occur have been computed at that point in the flow. Relocating the retry after classification, rather than merely widening its condition, is what makes it reachable at all.

The framework also supports \emph{multiple prompt versions} and \emph{multiple models}. A \texttt{-{}-compare-prompts} mode runs every prompt template on each design/seed, and a \texttt{-{}-compare-models} mode runs every model listed in \texttt{config.LLM\_MODELS} (overridable via the \texttt{LLM\_MODELS} environment variable) across the full matrix, so prompt and model effects can be compared side by side. Each run records first-shot generation time and correction time separately (\texttt{llm\_duration\_s}, \texttt{llm\_correction\_s}) so model speed stays comparable no matter how often the retry fires. Chain-of-thought is disabled for all models so they are evaluated on equal footing. The complete dataset can be cleanly rebuilt in one invocation using \texttt{-{}-fresh} (drops the existing CSV before the run) combined with \texttt{-{}-with-reference} (regenerates the reference baseline in the same pass).

A separate utility script, \texttt{scripts/rerun\_sta.py}, replays OpenSTA on every existing run's saved netlist and SDC using the current TCL — without re-calling the LLM or Yosys. This is used whenever the STA stage or coverage parser is changed, to upgrade the dataset deterministically ($\sim$0.1\,s per run, so about a minute for the full dataset) rather than re-sampling the LLM.

\section*{Benchmark Set}
The benchmark suite contains ten RTL designs, each paired with a trusted reference SDC under \texttt{designs/reference/}. The first six exercise clocking, port coverage, and basic timing paths. The remaining four were added later, once every model was reaching $\sim$100\% on the simpler designs, to reopen a measurable gap between models and between prompt versions:

\begin{table}[h]
\centering
\begin{tabularx}{\textwidth}{>{\ttfamily\raggedright\arraybackslash}p{0.23\textwidth} X}
\toprule
\textbf{Design} & \textbf{Purpose} \\
\midrule
simple.v & Minimal sanity-check design for verifying the end-to-end flow \\

fsm.v & Small finite-state machine benchmark \\
adder.v & Registered arithmetic datapath \\

\midrule
async\_in.v & Asynchronous input through a 2-flop synchronizer \\
cdc\_sync.v & Two-clock clock-domain-crossing synchronizer \\

mult\_mcp.v & Multi-cycle $16\times16$ multiply at a tight 1.5\,ns period \\
\bottomrule
\end{tabularx}
\end{table}

One exception recurs across the suite rather than belonging to any single design: every design with an asynchronous reset --- \texttt{counter}, \texttt{fsm}, \texttt{shift\_reg} and all four added designs --- must \texttt{set\_false\_path} on \texttt{rst\_n}, since the reset is not a timed data path. So \texttt{set\_false\_path} itself is a baseline requirement, not a marker of the harder designs.

What makes the four added designs harder is the additional, design-specific construct each requires beyond \texttt{create\_clock} and the I/O delays. \texttt{async\_in} extends the false-path idea to a \emph{data} port: the asynchronous input feeding the 2-flop synchronizer must be false-pathed as well (\texttt{set\_false\_path -from [get\_ports async\_in]}), not just the reset. \texttt{cdc\_sync} needs \texttt{set\_clock\_groups -asynchronous} between its two clocks. \texttt{clkdiv} needs \texttt{create\_generated\_clock} to time the divided domain. \texttt{mult\_mcp} needs \texttt{set\_multicycle\_path 2} so the slow multiply meets timing at the tight 1.5\,ns period. A model that omits the required construct lands directly in \texttt{partial\_coverage} (an untimed domain) or a genuine \texttt{timing\_violation} --- exactly the gap these designs were meant to expose. Of the four, \texttt{async\_in} is the mildest (it reuses a command the model has likely already applied to the reset), while \texttt{clkdiv} and \texttt{mult\_mcp} introduce genuinely new constructs that no model reliably gets right.

\section*{What the Framework Measures}
Each run records both correctness and QoR-related information. The current CSV schema captures:
\begin{itemize}[leftmargin=*,nosep]
    \item metadata: design name, top module, model name, seed, prompt version, run directory;
    \item structural properties of the produced SDC: number of extracted commands, presence of \texttt{create\_clock}, number of input and output delay statements;
    \item synthesis metrics: success status, runtime, total cell count, chip area;
    \item timing metrics: STA success, WNS, TNS, minimum slack, timing-met flag, number of setup violations, no-paths detection;
    \item \textbf{per-path-group coverage}: path counts and worst-slack for the in2reg, reg2out, and reg2reg groups, plus a \texttt{coverage\_complete} flag indicating whether the required input/output timing was actually analyzed;
    \item semantic classification: primary label, all labels, and a short rationale.
\end{itemize}

This is a strong design choice because it allows the project to separate several qualitatively different outcomes:
\begin{itemize}[leftmargin=*,nosep]
    \item fully accepted constraints (full path-group coverage, timing met),
    \item \emph{partial-coverage} constraints that pass timing only on the subset of paths that were analyzed (e.g. register-to-register only),
    \item syntactically accepted but ineffective constraints (no timing paths at all),
    \item timing-violating constraints,
    \item synthesis or STA failures caused by bad constraint content.
\end{itemize}

\section*{Key Findings}

\paragraph{1. Tool acceptance is not a valid success criterion.} This is the project's central methodological result and it shapes every number above. A static timing analyzer only times a path when both endpoints carry a clock reference; an unconstrained port is \emph{silently skipped}, not reported as an error. A constraint set that forgets to attach \texttt{-clock} to its I/O delays therefore produces a clean, violation-free STA report --- earned entirely on register-to-register paths, which are timed by \texttt{create\_clock} alone and essentially cannot fail. Under \texttt{v1\_base} this \texttt{partial\_coverage} pattern is the dominant failure (for example 25 of 50 runs for \texttt{granite4.1:8b}). Any evaluation that simply asks ``did the tool accept it?'' would score these as successes. The framework instead issues independent per-path-group queries and compares the groups actually analyzed against those the design structurally requires, so a run is \texttt{ok} only when the input$\to$register and register$\to$output paths were genuinely checked.

\paragraph{2. Prompt design dominates every other factor.} Moving from \texttt{v1\_base} to \texttt{v2\_base} lifts the aggregate success rate from 19\% to 73\%. The entire difference is two structural requirements: name the clock with \texttt{-name}, and attach \texttt{-clock} to every I/O delay (delay \emph{values} are deliberately left to the model). No other intervention in this study comes close --- the full two-level correction ladder adds a further 10 points. The practical implication is that constraint-generation quality is governed less by model capability than by whether the prompt pins down the structural contract the timing tool needs.

\paragraph{3. Generating and self-repairing are independent abilities.} The clearest single result in the dataset: \texttt{gemma4:e2b} and \texttt{minimax-m3:cloud} both generate at exactly 80\% on \texttt{v2\_base}, yet after correction one is unchanged at 80\% and the other reaches 98\%. Ranking models on one-shot accuracy would have called them equivalent. Repair ability is a distinct axis and must be measured separately.

\paragraph{4. Capable models repair; small models actively regress.} Of the 80 runs that entered the correction loop, 29 (36\%) were repaired and 22 (28\%) came out \emph{strictly worse} --- and the split is almost perfectly stratified by model strength:

The two strongest models repair 16 of 21 attempts with \emph{zero} regressions. The weakest, \texttt{gemma4:e2b}, repairs nothing at all and breaks five of ten. Twenty-one of the 22 regressions turned an SDC the tool had accepted into one it rejects outright: shown its own error and asked to fix it, a weak model rewrites too aggressively --- stripping \texttt{[get\_ports \dots]} wrappers, inventing flags --- and destroys syntax that previously worked. \textbf{A feedback loop is therefore not uniformly beneficial: below a capability threshold it is actively harmful}, and reporting only the aggregate success rate would hide this, because a run that is already \texttt{ok} never enters the loop and so the headline figure can only ever rise.

\paragraph{5. Feedback quality decides whether correction helps or harms.} An initial single-retry design that returned only the raw tool symptom repaired just 8\% of attempts while regressing 26\%. Diagnosing those failures showed successful repairs were small edits while failures were expansions. Three changes followed: the correction prompt now demands minimal edits, the symptom names the exact ports or violating path group, and a second level supplies an object dictionary. The repair rate rose from 8\% to 36\% on the same models and designs.

\paragraph{6. The residual failures are naming and application, not comprehension.} \texttt{clkdiv} is the sharpest case: \textbf{no model, on any seed, solves it first try (0/30)}, yet the object dictionary alone rescues 13 of 30. The models know they need a \texttt{create\_generated\_clock}; what they cannot do is name the target, because RTL signal names do not survive synthesis. A representative trajectory shows the two defects separating cleanly across levels:

\texttt{mult\_mcp} is the same story one step further out: 26 of 30 runs emit a \texttt{set\_multicycle\_path} at some point, but only 6 pass. The command is known; what fails is applying it to the right objects with the right argument order. Across the whole study, the single dominant cause of failure is the gap between the \emph{RTL} the model is shown and the \emph{gate-level netlist} the analyzer works on.

\paragraph{7. Failure modes differ qualitatively by model.} With the classifier distinguishing SDC-text defects from semantic gaps, \texttt{syntax\_error} --- an invented command option such as \texttt{-edge}, \texttt{-relative} or \texttt{-add\_shift} --- is the dominant \texttt{v1\_base} failure for every local model (7--21 runs each). \texttt{minimax-m3:cloud} produces \textbf{zero} syntax errors under either prompt: it never hallucinates a flag. That single measure separates the cloud model from the local ones more cleanly than the success rate does.

\paragraph{8. Constraints do not change the circuit, only its evaluation.} Cell count and chip area are identical to the reference for all 600 runs, because the SDC is read only by the timing analyzer and never reaches synthesis. Consequently no run can be judged on area or cell count, and slack magnitude is not a merit either: a value \emph{above} the reference simply means a looser, under-constrained I/O budget. What the per-group slack does reveal is calibration --- \texttt{minimax-m3:cloud} picks one delay value and holds it across seeds, sitting at or beside the reference, whereas the smallest models scatter their choice from 0 to 2\,ns run to run.

\section*{Conclusions}
The study set out to ask whether an LLM can produce synthesis constraints good enough to drive a real STA flow, and whether it can repair them when told what went wrong. Both answers are qualified yes, with the qualifications carrying most of the information.

On \emph{generation}: with a prompt that states the structural contract, five of six models exceed 70\% and the best reaches 80\% first-shot, with six of ten designs solved perfectly. But the measurement only means something because coverage is verified --- under the naive ``did the tool accept it'' criterion, a large share of the \texttt{v1\_base} failures would have been scored as successes.

On \emph{self-repair}: it works, and it is worth roughly a third of the remaining failures (36\% repaired, aggregate 73\%$\to$83\%), but only for models above a capability threshold and only with feedback that is precise and demands minimal edits. Below that threshold the same loop is destructive, and the aggregate success rate structurally cannot show it.

The deepest finding is where the residual difficulty actually lies. It is not that models fail to understand clock division or multi-cycle timing --- they name the right construct unprompted. It is that they cannot reliably refer to objects in a netlist they have never seen, having been shown only RTL. That is a concrete, addressable gap: supplying the legal object vocabulary alone converted \texttt{clkdiv} from 0/30 to 14/30 without revealing anything about the reference solution.

Finally, a methodological caution that generalizes beyond this project: every headline number here can be made to look better by measuring it slightly wrong. Pooling corrected and uncorrected prompt versions inflates the prompt effect; reporting success rate without coverage inflates everything; reporting it without regressions hides that the loop damages weak models. The instrumentation, not the models, was the hardest part to get right.

\section*{Possible Future Steps}
The results point to four follow-ups, ordered by how directly they attack the findings above.

\begin{enumerate}[leftmargin=*,nosep]
    \item \textbf{Close the namespace gap at generation time.} Finding~6 shows the dominant residual cause is that models cannot name post-synthesis objects. Supplying the object vocabulary \emph{in the generation prompt} (a \texttt{v3}), rather than only as correction level~2, would test whether \texttt{clkdiv} can be solved first-shot instead of repaired. This is the cheapest intervention with the largest expected effect.
    \item \textbf{Separate iteration depth from feedback strength.} The present ladder increases help and attempt count together, so a repair at level~2 cannot distinguish ``needed more tries'' from ``needed the dictionary''. Two conditions at equal depth --- constant feedback versus escalating feedback --- would separate them, and a convergence curve over 5 attempts would show whether persistence alone ever suffices. Attempt history in the prompt becomes necessary at that depth, since without memory a fifth attempt is merely a first attempt resampled.
    \item \textbf{Guard the weak models against themselves.} Finding~4 shows 21 of 22 regressions turned an accepted SDC into a rejected one. A validity gate --- discard a correction that introduces an unknown command or flag and keep the previous version --- would make the loop monotone, and would test whether weak-model regression is a generation problem or merely an unguarded-loop problem.
    \item \textbf{Make synthesis constraint-driven.}.For now, the netlist of all runs is invariant with respect to the SDCs, so no run can currently be judged on area or power. Feeding the SDC to the mapper (via an OpenROAD-style resizer) would let constraint quality shape the implementation and open the harder question: can a model \emph{safely relax} timing to reduce area without breaking function? That requires signing the resulting netlist off against the \emph{reference} SDC, so that under-constraining cannot masquerade as a QoR win.
\end{enumerate}

Two smaller items support the above: more seeds on the accurate models to tighten the interval around the $\sim$80\% generation ceiling, and further hard designs (interacting exceptions, deeper CDC, case analysis) now that the construct-forcing approach is validated.
